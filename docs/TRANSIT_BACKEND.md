# 교통자료와 계산

교통 backend는 실제 정류장 방문·운행 시각·보행 연결에서 정류장 통과와 배차 간격, 노선 출발, 여정, 구간 소요를 계산한다.
조회 실행이 계획의 대상·시기·조건을 그대로 넘기고, backend는 계산값과 원본 행 참조, 자료 판을 함께 돌려준다.

## 자료 준비

지역별 입력은 `DLLIO_REGION`이 지정한 디렉터리에서 읽는다. 경로를 생략하면 [examples/solmoe](../examples/solmoe/)를 사용한다. [`backend/region`](../backend/region/region.go)이 `region.json`에서 지역 이름, PostgreSQL database, 지도 검색 범위와 요금 구분을 읽는다.

| 지역 디렉터리 내 경로 | 내용 |
|---|---|
| `region.json`, `prior.md` | 지역 설정과 모델에 전달할 지역 지식 |
| `complaints/<번호>.md`, `complaints/dates.json` | 민원 원문과 접수일 |
| `priors/areas.json` | 지역 지칭과 행정동 목록의 대응 |
| `transit/revisions.json`, `transit/lineage.json` | 자료 판·원천 파일과 노선 이전 번호 |
| `streets/`, `boundaries.geojson` | 보행망 원본·출처와 행정동 경계 |
| `build/` | 전처리 결과 |

전처리는 Python package [`dllio_preprocess.network`](../preprocess/src/dllio_preprocess/network/)가 수행한다. [실행 환경](../WORKFLOWS.md#입력과-실행-환경)에 지정한 기존 interpreter로 `-m dllio_preprocess.network.<모듈>`을 실행하고, `--region`으로 지역 디렉터리를 전달한다.

| 모듈 | 하는 일 | 출력 |
|---|---|---|
| `streets` | OpenStreetMap에서 보행망 원본을 내려받는다 | `<지역>/streets/` |
| `build` | 자료 판에 지정된 원천 파일에서 정류장·운행·방문 순서·원본 행 번호·장소·보행 연결을 구성한다 | `<지역>/build/journey/<판>.json`, `<지역>/build/journey-provenance.json`. `--out`으로 결과 루트를 지정할 수 있다 |
| `catalogue` | 각 자료 판의 연결망에서 장소 catalogue를 구성한다 | `<지역>/build/catalogue.json` |
| `lineage` | `--xlsx`로 지정한 시간표의 시트 이름에서 노선 이전 번호를 읽는다 | `<지역>/transit/lineage.json` |
| `map_context` | `<지역>/boundaries.geojson`의 행정동 경계를 지도 배경용으로 단순화한다 | `<지역>/build/map-context.json` |
| `load` | 지역의 전처리 결과와 자료 판을 `region.json`의 database에 적재한다. 스키마는 [`transit`](../backend/db/schema.sql)이다 | PostgreSQL |

[`check_network.py`](../test/network/check_network.py)는 운행 수와 장소의 정합을 점검한다. 공휴일 표는 `tools/build_holidays.py`로 만든다.

전처리는 원천 기록의 정류장 방문과 운행 시각·순서를 저장한다. 질의는 목적지 조건으로 진행 방향을 구분한다.
방문은 자료 판·운행 기록·방문 순서별 한 행이며, 시각을 알 수 없으면 NULL이다. 정류장에는 좌표가 놓인 행정동('남구 삼산동')을 행정동 경계 자료에서 붙여,
지역 prior의 행정동을 그 정류장으로 바꿀 수 있게 한다.

## 운행 연결

제공 시간표는 `trip_id`를 한 운행, `stop_sequence`를 방문 순서로 사용한다. 관측 기록은 같은 날·같은 차량·같은
패턴의 기록을 도착 시각 순으로 정렬하고, 정류장 순번이 되돌아가는 지점에서 운행을 나눈다. 복원한 운행은 왕복
단위다. 시각은 운행일 0시부터의 초이며 자정 이후 운행은 24시를 넘겨 센다. 출발시각이 없거나 도착보다 이른 기록은
승차 후보에서 제외하고 도착 근거는 유지한다. 중간 정류장에서 기록이 시작된 운행, 자정을 넘긴 운행과 양산 경계에서
잘린 운행을 표시한다. 관측 기록은 같은 차량이라도 패턴 번호가 바뀌면 다른 운행 기록이 되며, 기록 사이를
잇지 않는다. 단말이 지나간 정류장을 기록하지 않은 경우는 그 방문이 없는 기록으로 그대로 둔다.

순환 운행에서 같은 정류장을 다시 방문하면 해당 방문 순번을 보존한다. 승차 뒤의 방문만 하차 후보가 된다.

### 장소

괄호와 공백을 뺀 이름이 같고 150m 안에서 서로 이어지는 정류장을 한 장소로 묶는다. 이름이 다른 정류장은 합치지
않는다. 길 건너 마주 보는 정류장은 한 장소가 되므로, 갈 때와 올 때의 정류장이 같은 장소로 읽힌다.

### 자료 판

지역 디렉터리의 `transit/revisions.json`은 자료 판을 시간 순서로 정의한다. 각 판에는 유효 기간과 관측일, 원천 파일 경로를 지정한다. 알 수 없는 날짜는 `null`로 둔다. 별도로 알려진 노선 변경도 날짜와 함께 기록하며 날짜가 없으면 `null`로 둔다.
민원 접수일은 같은 지역의 `complaints/dates.json`에서 읽는다.

계획은 접수일에 유효한 판(`revision_at`)을 선택한다. 유효 기간으로 결정할 수 없으면 가장 최근 판을 선택한다. 결과에는 선택한 판, 관측일과 해당 날짜 이후 질의한 노선에 알려진 변경을 반환한다. 판의 적용 기간과 개편 경계는 지역별 revision 입력으로 정한다.

### 이전 번호

[`network.lineage`](../preprocess/src/dllio_preprocess/network/lineage.py)는 `--xlsx`로 지정한 시간표 파일의 시트 이름에서 노선 이전 번호를 추출한다. 시트 하나가 노선 하나이고,
시트 이름이 그 노선이 이어받은 이전 번호(`543(구857)`, `울주81(구 울주01)`)나 신설(`741(신설)`)을 적는다. 한 번호를 여러 노선이
이어받은 경우(`1144(구1137)`, `1154(구1137)`)는 그 노선 모두에 이전 번호로 남는다. 이 모듈의 출력은 시트 이름에 명시된 노선 번호 대응이다.

개편 전 자료는 이전 번호로 수록되어 있다. 조회 도구는 질의한 번호의 이전 번호, 그 번호를 이어받은 지금 번호,
그중 질의한 자료에 있는 번호를 결과에 함께 반환한다. 실제 조회에는 요청에 지정된 번호를 사용한다. 개편 전 자료를 조회할 번호는 시민이 말한 번호이거나, 정류장 겹침을 근거로 판정 모델이 고른 번호다. 이전 번호 표기는 판정의 참고로만 쓴다.

### 노선과 변형 운행

노선은 노선 번호(마지막 괄호를 뺀 노선명)다. 같은 번호의 패턴은 판정 없이 그 노선에 속한다. 번호마다 정류장을 가장 많이 지난
온전한 기록을 기준 기록으로 두고, [`round_trip`](../preprocess/src/dllio_preprocess/network/round_trip.py)이 기록마다 기준 기록과 정류장 순서가 어떻게 겹치는지를 저장한다.
겹치는 위치와 비율, 기록의 모양(`shape`)이다. 분류는 왕복(`loop`), 출발 방향 편도(`out`), 복귀 방향 편도(`back`), 기준 기록과 다른 변형 운행(`variant`)이다. 편도 기록으로 구성된 노선에서는 기준 기록의 반대 방향을 `back`으로 분류한다. 변형 운행의 경로는 해당 기록의 실제 정류장 순서로 반환한다.
노선 번호로 묶고 정류장마다 시각순으로 정렬하면 같은 정류장의 운행 계열이 된다.

## 지역과 자료 범위

장소 catalogue는 지칭과 원천 정류장을 연결한다. 정류장 inventory만 있고 운행 기록이 없는 경우는 미수록으로 다루고,
해당 운행 자료에서 확인한 0회와 구별한다. 조회 지점이 자료의 운행 범위에 없으면 미수록 상태를 반환한다.

## 조회 도구

[`backend/tools`](../backend/tools/tools.go)는 분석 단계가 같은 프로세스에서 부르는 조회 도구다. 읽기 전용 계정 `dllio_read`로
`transit` 스키마를 읽고, 시작할 때 판마다 연결망과 구간 소요 표, 장소 catalogue를 메모리에 올린다.

| 조회 | 하는 일 |
|---|---|
| `/sql` | SELECT 한 문장을 read-only transaction의 prepared statement로 실행한다. 쓰기 연산과 여러 statement는 거절한다. 최대 2,000행과 전체 행 수를 반환한다 |
| `/query` `journeys` | 보행·환승 여정 |
| `/query` `map` | 노선별 실제 경유 순서의 지도와 원문 정류장 위치 |
| `/query` `segments` | 구간 소요 견적과 실제 운행 기록의 소요 |
| `/search`, `/place`, `/catalogue` | 장소 검색, 장소 정보, 자료 판과 노선 목록 |

SQL 함수는 정류장 통과 `calls`, 계열 요약 `calls_summary`, 노선 출발 `route_starts`, 날짜의 판 `revision_at`, 시각 표기 `hhmm`이다.
조회마다 입력, 결과, 자료 판·연결망 버전·원천 hash, 이전 번호 대응을 묶고, 그 묶음의 hash로 근거 ID(`e_…`)를 만든다.
같은 입력과 같은 자료면 같은 근거 ID가 나온다.

## 정류장 통과와 배차

배차 간격은 물리 정류장 ID와 노선 번호로 방문을 그룹화하고 시각순으로 계산한다. 같은 정류장·노선의 변형 운행과 반복 방문도 같은 계열에 포함한다. 방면은 결과의 표기 정보로 사용한다. 계획 자료는 출발 시각, 관측 자료는 도착 시각을 사용하고,
종착 방문을 제외한다. 여러 정류장을 지나는 같은 버스가 각 계열에 나타날 수 있으므로 계열을 합산하지 않는다.

방향은 질의의 목적지로 정한다. 목적지가 있으면 통과마다 같은 운행 기록 안에서 출발지 뒤에 목적지에 닿는 시각과
차내 시간을 붙인다. 같은 정류장을 두 번 지나는 운행은 두 통과가 각자의 도착 시각을 가지므로, 고리를 돌아 늦게
닿는 통과와 바로 닿는 통과가 시각으로 구분된다. 기록 안에서 목적지에 닿지 않는 통과는 따로 표시하며,
단축·분기 운행과 기록이 목적지 전에 끝난 경우가 여기에 든다.

`calls`의 `time_kind=departure`는 승차 지점의 실제 출발시각 사이에서 간격을 잰다. `direct=true`는 목적지에 닿기 전 같은 승차 정류장의
마지막 방문을 고른다. 반환 전 같은 정류장을 지났던 통과와 반환 후 목적지로 나가는 출발을 구별한다. 조회 실행은 목적지가 있는 정류장 출발에서 켠다.

`route_starts`는 노선 번호마다 한 줄로 시간대 안에 출발한 편의 수·평균·최대 간격, 변형 운행 수와 첫차·막차 시각을 계산한다.
왕복(`loop`)과 출발 방향 편도(`out`)는 출발로 한 번씩 세고, 복귀 방향 편도(`back`)는 제외한다. 앞 정류장을 놓친 운행은 첫 기록 시각으로 센다. 표기하는 출발 정류장은 온전한 기록이 가장 많이 출발한 곳이다.

정류장이 여러 개인 장소의 정류장 출발은 노선 번호마다 한 줄이다. 같은 운행 기록에서 방문 순번이 세 번 안쪽으로 이어지면 그 장소를 한 번 지나는 것으로 보고, 그 동안의 시각을 평균해 그 장소에 오는 시각으로 쓴다.

## 여정

[`router.go`](../backend/journey/router.go)는 직통과 한 번 환승하는 운행 조합을 열거한다. 출발·도착 기준점은 장소 후보의 그 판 첫 정류장 위치다.

| 입력 | 역할 |
|---|---|
| `Time`, `ArriveBy` | 출발 기준 시각 또는 도착 목표 시각 |
| `MaxWalkMeters` | 출발 접근·환승 이동·도착 접근을 합한 총 도보 예산(조회 실행은 600m) |
| `MaxTransfers` | 환승 없음 또는 최대 1회(조회 실행은 1회) |
| `WalkSpeed`, `TransferMarginSeconds` | 보행 속도(1.2m/s)와 다음 차량 승차까지 확보할 여유(90초) |
| `DepartureStart`, `DepartureEnd` | 출발편을 셀 시간대 |
| `FocusRoutes` | 원문이 말한 노선 |
| `CollectBoardings` | 출발편별 도착 가능 여정을 모아 센다 |

출발 기준 탐색은 기준 시각부터 4시간, 도착 목표 탐색은 목표 이전 4시간 안에서 계산한다.
출발 기준에서는 도착시각·도보·환승횟수, 도착 목표에서는 출발시각·이동시간·도보·환승횟수를 비교하고,
한 후보가 모든 기준에서 다른 후보보다 유리한 경우 해당 후보를 우선한다. 대표 여정에는 효율적인 후보, 원문 노선의 후보, 도보 범위를 넓혀
다른 지점에서 타는 후보를 함께 두고, 비슷한 노선 조합을 묶어 최대 12개를 돌려준다.
출발편을 셀 때는 원본 trip과 첫 승차 offset으로 편을 구별하고, 여러 환승 조합이 있어도 한 출발편으로 센다.

각 여정은 승하차 정류장·시각·운행 식별자·원본 행 번호, 구간별 도보·대기·차내시간을 돌려준다. 버스 지도 선은 정차 순서를 잇고,
보행 선은 도로망에서 계산한 경로를 사용한다. 정류장 접근을 연결할 수 없으면 `coverage_gap`, 지정 범위의 여정이 없으면 `no_journey`,
후보가 있으면 `ok`다.

## 보행과 환승

보행망은 공개 OpenStreetMap 도로·보행 연결을 사용한다. 보행 금지·비공개 접근과 전용도로를 제외하고, 보행 방향 제한과 노드 연결을 보존한다.
정류장을 가까운 도로 구간에 연결할 때 최대 35m의 접근 연결을 허용하고, 이 연결의 길이를 도보 거리와 근거에 포함한다. 정류장마다 걸어서 닿는
정류장은 1,800m까지 미리 계산한다. 같은 장소의 반대편 정류장도 보행망을 통해 연결한다. 환승은 선행 차량의 도착 이후 보행시간과 환승 여유를
확보한 경우에만 연결한다. 보행망 출처는 지역 디렉터리의 `streets/source.json`에 저장하고, 원본 hash와 변환 범위는 전처리가 생성하는 `build/journey-provenance.json`에 저장한다.

## 구간 소요 견적

[`segments.go`](../backend/segments/segments.go)는 운행 기록이 연달아 지난 두 정류장 사이의 시간을 모든 노선에서
모아 구간별 소요를 낸다. 관측 자료는 실제 시각, 제공 시간표는 계획 시각이다. 한 구간은 앞 정류장 도착부터 다음
정류장 도착까지라 정차 시간을 포함한다. 시각 없이 지난 정류장은 건너뛰고 다음 시각이 있는 정류장까지를 한 구간으로
둔다. 요청 시간대에 같은 구간의 기록이 세 건 이상이면 그 시간대 값을, 아니면 하루 전체 값을 쓰고 어느 쪽인지
표시한다. 구간 값은 중앙값과 사분위, 표본 수다.

정류장 순서는 질의가 직접 주거나, 노선 기록에서 출발 정류장 뒤에 도착 정류장을 지나는 가장 많은 운행의 순서를 쓴다.
순서를 따라 이웃한 정류장의 구간을 잇고, 이웃 구간 기록이 없으면 기록이 연달아 지난 더 먼 정류장까지의 구간을,
그것도 없으면 직선 거리와 같은 자료의 정류장 간 평균 속도를 쓴다. 노선 기록이 두 지점을 실제로 지난 운행의 소요도
함께 돌려주어 견적과 나란히 읽는다.

## 개편 전후 비교

개편 전후를 함께 보는 조회는 같은 조건을 두 판에 각각 실행하고, 개편 전 판에서는 개편 전 쪽 노선으로 조회한다.
결과가 없는 판은 그 사실을 남기고 비교에서 뺀다. 블록은 두 판의 결과를 한 표·차트에 나란히 놓는다.
노선 경로는 판마다 지도를 두고, 개편 전에만·후에만 지나는 정류장을 정리한다.
