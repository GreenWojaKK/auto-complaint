# 민원 표현과 읽기 수준

같은 민원을 서로 다른 추상 수준으로 표현한다.

- **L2**: 여러 민원에 공통으로 적용되는 교통 문제 유형이다. 예: “필요한 구간·시간대의 운행 횟수가 적거나 배차간격이 길다”.
  유형의 정의와 경계는 [catalog](L2_CATALOG.md)에 둔다.
- **L1**: 그 문제를 이 시민의 경험과 요구로 구체화한 행정 검토용 요약이다.
- **원문**: 시민이 쓴 전체 글이다. 화면에서 그대로 읽는다.

민원 읽기는 추상에서 구체로 진행한다. 판정 모델이 원문 전체로 L2 유형을 고르고, 추출이 유형마다 이동을 뽑고,
계획 단계의 언어 모델이 고른 유형과 그 근거, 이동을 뼈대로 L1을 쓴다. 원문에서 따로 요약을 만든 뒤 유형을 붙이는 순서로 바꾸지 않는다.

## L1

| 항목 | 내용 |
|---|---|
| `headline` | 한줄요약. 장소와 원문에 있는 시간 맥락을 앞에 두고 이용 불편을 짧게 붙인 명사구 |
| `situation` | 이 시민이 어디서 어떤 이동·이용을 하며 어떤 불편을 겪는지. 한 항목에 한 사실, 1~4항목 |
| `requests` | 행정이 검토할 조치 요청. 조치 하나를 담은 명사구에 "요청"을 붙여 맺는다 |
| `replies` | 행정이 업무 사실로 답할 문의와 처리 절차에 대한 부탁 |

- 시민의 말을 옮기지 않고, 뜻을 그대로 유지한 행정 문서 문체로 다시 쓴다. 오탈자·비문을 바로잡고 구어·감정 표현은 중립 표현으로 바꾸며,
  대상·수치·시기·조건·요구의 관계는 바꾸지 않는다.
- 상황은 추출한 이동을 기준점으로 삼고, 유형 이름이나 명제 문장으로 바꾸지 않고 시민의 경험으로 쓴다.
  노선 변경 이력, 시각 목록, 배차 수치는 한줄요약에 넣지 않는다.
- 요청은 특정 경유지, 조건부 제안, 대안을 지우지 않는다. 조치나 대상 조건이 다르면 항목을 나눈다. 요구가 없으면 비우며, 이것은 정상 결과다.
- 조회하지 않는 문제와 측면도 L1에 쓴다. 조회하지 않는 측면에 대한 상황과 요청은 시민이 말한 조건과 값으로 쓰고, 시민이 예로 든 노선·장소는 옮기지 않는다.
- 원문에 없는 시간대·이동 방향·요구·원인·수치를 더하지 않고, 원문의 시각을 해석해 덧붙이지 않는다("4시 반"을 "오후 4시 반"으로 쓰지 않는다).

지시는 [계획 지시](../prompts/analysis/plan.md)다. 출력 형식이 `situation`의 항목 수(1~4)를 강제한다.

## 화면

뷰어의 민원 패널은 한줄요약, 원문, 문제 상황, 요청, 문의, 문제 유형, 확인 계획 순서로 보인다.
문제 유형은 유형의 화면 이름(측면을 고른 유형은 고른 측면의 이름)과 유형별 이동이다. 확인 계획은 답한 질문과 조회 조건, 답이며,
질문을 누르면 그 답을 보여 주는 페이지로 간다. 화면에는 자료의 한계나 내부 처리 설명을 쓰지 않는다.
